Topic: How the website was built, system structure, data/API sources, and building height logic.
Course demo: BLUE / Digital City
Area: Oxnehaga, Huskvarna
Date: March 12, 2026
Single-page web GIS app ArcGIS JS API 4.30 Live + local datasets BIM + transport + safety

This project is an interactive 3D map for Oxnehaga. It combines local GeoJSON data, live transport and environment APIs, and BIM model visualization. The goal is to support decision-making and explain conditions around mobility, service access, and safety.

1) How I Built It

  • I used a single-page architecture with index.html as the main app shell and ArcGIS SceneView for 3D.
  • I separated features into modules (wind, PM2.5, cloud layer, bus simulation, elevation provider, BIM viewer logic).
  • I loaded local city data from /data GeoJSON files and combined it with selected live APIs.
  • I added panel-based UX (Menu, Digital City, Information) so each part of the demo has a clear function.
Main files: index.html styles.css + ui-2026.css bus15.js elevationProvider.js pm25Live.js windLive.js cloudWms.js data/*.geojson

2) System Structure Behind the Website

User (browser) -> index.html UI + ArcGIS SceneView -> Local layers (GeoJSON files in /data) -> Remote layers/APIs (transport, weather, air, cloud, shelters) -> Analysis logic (distance, routing, elevation, simulation) -> Results in side panels and map graphics

UI Layer

Header, menu tab, digital panel, BLUE/info panel, modals, BIM controls.

Map Layer

ArcGIS SceneView with SceneLayer, GeoJSONLayer, FeatureLayer, and GraphicsLayer overlays.

Data/Service Layer

Local GeoJSON + external APIs for route, departures, weather, air quality, wind, and cloud imagery.

4) Building Height and Elevation Logic

Building extrusion in the 3D map

  • Building polygons come from data/Main_byggnad.geojson.
  • Extrusion uses attribute b_Hight_m (meters).
  • If b_Hight_m is missing, fallback extrusion is 5 m.

Special simulation override

  • Two selected simulation buildings are forced to 18 m for a clear visual scenario.

Building information modal note

  • The current modal uses a demo factsheet (mock), including a sample height value of 18.5 m.
  • So modal text is demonstration content, while map extrusion is attribute-driven.

Elevation for distance/route analysis

  • Primary in-app terrain analysis uses ArcGIS ground elevation query.
  • Additional elevation support is provided by elevationProvider.js and a hosted elevation GeoJSON dataset (Hojder_Oxnehaga_1.geojson).
  • Fallback providers include OpenTopoData and Open-Meteo elevation endpoint when applicable.
Practical explanation for teacher:
Building height on the map is mostly from building attributes (`b_Hight_m`).
Height difference in route analysis comes from terrain elevation sampling.

6) Limitations and Next Steps

  • Some building info modal values are demo/mock and should be replaced by real IFC-derived metadata.
  • API keys are currently client-side; production version should move key usage to a secure backend proxy.
  • A formal metadata catalog can be added (source owner, update frequency, license).

7) Short Presentation Script (1 minute)

"I built a 3D web GIS for Oxnehaga using ArcGIS JavaScript API. The website is structured as one interactive page with separate modules for transport, weather, air quality, cloud and elevation. Most map layers are local GeoJSON files, and live information comes from APIs like ResRobot, OpenRouteService, Open-Meteo, SMHI datahost, NASA GIBS, and electricity pricing API. Building heights in the map are mainly driven by the building attribute `b_Hight_m`, with controlled overrides for specific simulation buildings. Elevation differences for walking/driving analysis are computed from terrain queries and the elevation provider dataset."
